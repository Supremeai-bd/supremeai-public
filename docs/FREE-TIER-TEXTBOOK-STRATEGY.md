### 🔴 আবিষ্কার ১ — "২৫টি সার্ভিস" আসলে **১টিই** চলতে পারে

Tower নিজেই বলছে `total: 25 services`। কিন্তু Render free tier-এর নিয়ম:

| সীমা                  | মান                                |
| --------------------- | ---------------------------------- |
| Free instance hours   | **৭৫০ / মাস / workspace** (শেয়ার্ড) |
| একটি always-on সার্ভিস | ৭৩০ ঘণ্টা = বাজেটের **৯৭%**         |

| ২৫টি always-on লাগত   | ১৮,২৫০ ঘণ্টা = **২৪ গুণ বেশি**       |
| বাস্তব `render.yaml`   | ৩টি `plan: free` web service       |

**কিন্তু আসল ফাঁদটা অন্য জায়গায়:**

```
Tower প্রতি ৮ মিনিটে health sweep চালায়  (index.ts:521)
Render-এর idle threshold: ১৫ মিনিট
→ ৮ মিনিট < ১৫ মিনিট, অর্থাৎ Tower যাকে probe করে তাকে প্রতিবার জাগিয়ে তোলে
→ Tower নিজে কখনো ঘুমায় না (৭৩০ ঘণ্টা) + তার peer-রাও জাগে
→ ৩ সার্ভিস × ৭৩০ = ২,১৯০ ঘণ্টা = বাজেটের ২.৯ গুণ
```

👉 **সিস্টেমটা নিজের মনিটরিং দিয়েই নিজের free tier খেয়ে ফেলছে।** এটা বাগ, নীতি নয়।
সমাধান সহজ: sweep বন্ধ করা নয় — **peer-দের probe করা বন্ধ করে Render-এর নিজের
health API-তে নির্ভর করা**, আর Tower-কে শুধু সার্ভিসের _অবস্থা_ জিজ্ঞেস করা।

## ২. "সিস্টেম নিজে ঠিক করবে" — সৎ সীমা

এটা বিশ্বাস করা দরকার: **engineering-এ কোনো সিস্টেম নিজে ঠিক হয় না।**
যা হয়, তা হলো **closure** — একটি সমস্যা নিজের সম্পর্কে এত তথ্য দেয় যে সমাধানটা
mechanically বেরিয়ে আসে।

তিনটি স্তর, ক্রমবর্ধমান ঝুঁকি:

| স্তর    | নাম                                | মানুষের হাত  | উদাহরণ                                                                   | আজ                            |
| ------ | ---------------------------------- | ----------- | ------------------------------------------------------------------------ | ----------------------------- |
| **L0** | Detect                             | ০           | guard লাল হয়, issue খোলে                                                 | ✅ আছে                        |
| **L1** | Auto-close (mechanically provable) | ০           | lockfile drift, `@types/node` parity, stale branch, dead path, env alias | ⚠️ আংশিক                      |
| **L2** | Propose (LLM + gate)               | ১ (approve) | TS error fix, test লেখা, dependabot major-এর migration                   | ❌                            |
| **L3** | Autonomous judgement               | ০           | "এই আর্কিটেকচার বদলানো উচিত কি"                                           | ❌ **এবং কখনোই হওয়া উচিত নয়** |

**আপনার constitution নিজেই এই সীমা স্বীকার করেছে:** ২৫টির মধ্যে মাত্র ১টি `fixable: true`।
সেটাই সঠিক বিচার। তাই লক্ষ্য হওয়া উচিত **L3 নয়, L1-কে ১০০%-এ নেওয়া এবং L2-কে নিরাপদ করা**।

### L1-এ কী কী genuinely auto-fixable (এবং আজ খোলা)

| সমস্যা                         | কেন mechanical       | আজ                       |
| ----------------------------- | -------------------- | ------------------------ |
| `@types/node` major > runtime | সংখ্যা তুলনা           | ✅ PR #48-এ গেটেড        |
| Dependabot patch              | soak + gate          | ✅ PR #48                |
| lockfile ↔ manifest drift     | `npm ci --dry-run`   | ⚠️ detect হয়, fix হয় না  |
| dead workflow path filter     | ফাইল আছে কি না       | ⚠️ হাতে সারাতে হলো       |
| stale branch / cache          | বয়স                  | ⚠️ ইস্যু #655              |
| `.env.example` legacy alias   | registry তুলনা        | ⚠️ warning মাত্র, fix নেই |
| shallow checkout census       | `git fetch --deepen` | ⚠️ self-heal আছে, ধীর    |
| README ব্যাজ ৪০৪               | HTTP GET             | ⚠️ হাতে সারাতে হলো       |

👉 এই ৮টির মধ্যে **৫টির fixer লেখা যায় সাধারণ Python-এ, LLM ছাড়াই**।
এখানেই আসল ROI — ৯৬% নিয়মে LLM ঢোকানোর আগে।

## ৩. "AI-জগতের আপডেট শোষণ করবে" — শুধু **একটি** শিল্প-অনুশীলন দিয়ে

মডেল প্রতি ২–৩ মাসে বদলায়। কোড যদি মডেল-নাম হার্ডকোড করে, প্রতিবার migration লাগে।

### কৌশল: **Golden-Eval-Gated Model Promotions (canary)**

আপনার হাতে ইতিমধ্যেই উপকরণ আছে — `evals/golden/suite.json`, ১০০ কেস, threshold ০.৯।

```
নতুন মডেল আসল → golden eval চালাও (১০০ কেস)
      │
      ├─ score ≥ 0.90 (baseline-এর সমান/ভালো)  → shadow → ১০% traffic → promote
      └─ score <  0.90                          → reject, baseline-এই থাকো
```

এতে "AI-জগতের আপডেট" মোকাবিলা হয় **কোড না বদলিয়ে, config + measurement দিয়ে**।
MCP Tower-এর `evals/golden` ফোল্ডার আর `ai_pr_evaluator.py` এই কাজের ভিত্তি।

**যা এখনো নেই (তাই এটাই প্রথম কাজ):**

1. Golden suite-কে **প্রতি মডেল-প্রস্তাবে** চালানো (আজ সপ্তাহে একবার)
2. Baseline score সংরক্ষণ (regression ধরা)
3. `route.yaml`-এ মডেল tier → শুধু সেখানেই বদল, কোডে নয়

এবং **আপনার PR #48-এর dependabot gate একই প্যাটার্ন** — soak + gate + tier।
অর্থাৎ আপনি ইতিমধ্যেই সঠিক প্যাটার্নটা একবার আবিষ্কার করেছেন; শুধু মডেলে প্রয়োগ করা হয়নি।

## ৪. তথ্য-স্থাপত্য: কোনো কিছু দুইবার নয়

আজ দুই রেপো = দুই সত্য (SECURITY.md একটায় আছে একটায় নেই, dependabot config ভিন্ন,
পাইপলাইন ৪৫৫ vs ২,৭৩৮ লাইন)। নিয়ম:

```
                    ┌──────────────────────────┐
                    │  supremeai (core/private) │  ← সত্যের একমাত্র ঠিকানা
                    │  constitution, evals,     │
                    │  schemas, guards          │
                    └────────────┬─────────────┘
                                 │ sync (GitHub API, CI job)
                                 ▼
                    ┌──────────────────────────┐
                    │    supremeai-public       │  ← পাবলিক আয়না, হাতে এডিট নিষিদ্ধ
                    └──────────────────────────┘
```

**নিয়ম ১:** `dependabot.yml`, `SECURITY.md`, `npm scripts`, `constitution` — **এক জায়গায়**।

### সপ্তাহ ৫–৬ · **T2: L1 auto-close ইঞ্জিন**

৮টি mechanical fixer (উপরের তালিকা)। প্রতিটির জন্য:
`detect → fix → PR → gate → auto-merge (mechanically provable হলে)`

**সফলতার মাপ: মানুষের হাত পড়া fix-এর অনুপাত ১০০% → ৪০%**

### সপ্তাহ ৭–৮ · **T3: L2 প্রস্তাবক**

LLM-proposed PR, কিন্তু **সবসময়** মানুষের approve + golden eval + full CI।
প্রথম দুটি কাজ: (ক) TS compile error fix, (খ) অনুপস্থিত test লেখা।

**গেট: L2-এর কোনো PR auto-merge হবে না। কখনো।**

### সপ্তাহ ৯–১২ · **T4: মডেল-প্রমোশন pipeline**

Golden eval → threshold → canary → promote। প্রথম সিদ্ধান্তটা **নেওয়া হবে না**
(অর্থাৎ আজকের মডেলই থাকবে) — শুধু pipeline + baseline বসানো হবে।

**গেট: নতুন মডেল score < baseline হলে reject, এবং সেটা লগে দৃশ্যমান।**
